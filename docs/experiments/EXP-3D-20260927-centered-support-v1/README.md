# 第三个场景零写入支持修复

状态：`GEOMETRY_SUPPORT_RESTORED_ENGINEERING_ONLY`。一次预先锁定的几何修复与同预算重训已完成。第三个场景的写入路径恢复，但重建质量不优于原结果；不替代原权重作为已验证更优模型。

## 根因与改动

旧体积为锚点相机坐标 `[-6,-4,0.05] .. [6,4,12.05]`，只覆盖前方。ai_003_001 的后续观测相机朝向后方，帧 0/1/2/5/6 的可见候选数为 69/0/0/0/0，没有候选点满足至少两视图支持，两个写入 proposal 均为零。

本次三个场景统一使用 `[-6,-4,-6] .. [6,4,6]`。体积仍为 12×8×12 m，8³ 网格、128 个候选不变。未修改 backbone、写入规则、双视图门槛、帧角色、训练预算或损失。`CarrierConfig` 默认保持原值；通过 `--spatial-mode anchor-centered` 显式启用。

方案在新几何评价前记录于 preregistration.json，只根据已观察相机故障制定，没有参数搜索或按场景选框。支持诊断只加载 context_a 和 stream 的 RGB/相机，不读取 query 姿态或标签、任何 depth。将所有 query 姿态/内参及媒体路径毒化后诊断逐项完全相同。这里的“支持”仅指两个视锥覆盖，不保证表面可见或无遮挡。

## 运行与结果

使用同一已校验 Hypersim TRAIN 数据、同一 seed=20260927，从头训练 100 步 A + 30 步 B。独立审计确认新旧初始全部 22 个 carrier 和 8 个 writer 学习张量逐 bit 相同。未从旧 checkpoint 移植几何 buffer。训练耗时 10.88 秒，峰值 CUDA 分配约 255 MiB；不含数据准备和全套测试。

下表为固定观测前缀 0/1/2/5/6 的支持，以及最终权重在原 12 个 TRAIN query 上的 OFF 重建评价。AbsRel 越低越好。

ai003 新几何逐前缀支持为 **0/0/0/3/4**：context_a 本身仍无双视图支持；stream 帧 5/6 到达后才恢复写入。初始化、零 fast 偏移下，完整观测前缀的 FUSE proposal 范数为 0.000334107，COMPLETE 为 0.000165016；旧配置均为 0。真实 B 训练的 10 步全部获得非零 writer 梯度，FUSE/COMPLETE/ALL 分别为 4/3/3 步。
