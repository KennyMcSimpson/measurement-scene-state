# EXP-3D-CAJU3D-ENGINE-V1：CAJU-3D 第一步——不含学习模块的 TTT 引擎

**结论：`STOP_AT_DEV`。** 方案中不需要学习的四个机制都没有超过 Core B（发布版权重加原始 TTT），所以按预注册规则不做确认：
- α 归一化、只看已覆盖像素的 TTT 损失；
- 几何参数与外观参数解耦；
- 入射角/深度跳变掩码；
- L2 锚梯度锥投影。

方案说明里的"关键工程发现"一半对、一半错：
- **对的一半**：原始 TTT 确实会冲掉 JN1 有选择的弃权。已观测视角的覆盖率从 0.685 升到 0.964，α 归一化 TTT 能把覆盖率保持在 0.689。
- **错的一半**：对未来查询来说，冲掉弃权反而有利。在发布版权重上，原始 TTT 仍然是最好的。

## 设计（[PROTOCOL.md](PROTOCOL.md)，2026-10-14 18:09:32 锁定，sha256 `e92c77ea…`）

- **底座**：发布版 DepthSplat（ZS）和 JN1（准确率目标的逆向 JEPA 检查点），尺度上限 0.1，从同一个 7 视角 CACHE 出发，跑 100 步。
- **变体**：
  - RAW：V1 的原始 TTT；
  - NORM：α 归一化，只看已覆盖像素；
  - NORM_DEC：NORM 加几何/外观解耦；
  - NORM_DEC_INC：NORM_DEC 加入射角/跳变权重和锥投影。
- **读出**：都用 Core B 读出，即 sqrt(R7 × F7)。
- **开发集**：从 ARKIT_SYSTEM 和 ARKIT_SYSTEM2 各按种子选 12 个扫描，共 24 个场所、48 个片段。JN1 训练时没有见过这些场所。
- **复用与核对**：复用已封存的 Core B、CACHE 和 R7。新算的 CACHE 与已封存的逐位一致（96 个查询，差值 0.0）。
- **选择规则**：从 7 个候选中取开发集均值最低者。如果它没有低于 Core B，就停止。

## 机制（已观测视角，48 个片段平均）

| 臂 | 覆盖率 | 已覆盖像素的归一化误差 | 不透明度 ≥ 0.5 的占比 | 查询视角覆盖率 |
|---|---|---|---|---|
| JN1_CACHE | 0.685 | 0.038 | 0.036 | 0.546 |
| JN1_RAW | **0.964** | 0.035 | 0.081 | 0.734 |
| JN1_NORM | 0.689 | **0.018** | 0.035 | 0.525 |
| ZS_CACHE | 0.993 | 0.051 | 0.147 | 0.744 |
| ZS_NORM | 0.976 | 0.022 | 0.133 | 0.689 |

- **原始损失**：它把未覆盖像素按满深度计入损失，所以会推高覆盖率和不透明度。
- **α 归一化损失**：它保持覆盖率，同时把已覆盖像素拟合得更准。
- **但未来查询需要的是覆盖**：F7 在未覆盖的地方回退到 R7，而 TTT 推到这些像素上的深度比 R7 更准。所以对未来查询而言，原始损失给出的覆盖反而带来更好的结果。

方案说的"把不透明度拉回约 0.70"没有观察到。实测高斯平均不透明度从 0.091 升到 0.148。

## 意义与下一步

- **第一步不成立**：方案的引擎改动没有超过 Core B。
- **JEPA 部分还要单独检验**：第二步（EXP-3D-CAJU3D-JEPAGATE-V1）以 Core B 为底座，用修正版 H-JEPA（带几何对齐）的潜空间创新挑像素，与深度一致性、入射角、随机三种挑法在相同剔除比例下比较，检验 JEPA 是否提供额外信息。
