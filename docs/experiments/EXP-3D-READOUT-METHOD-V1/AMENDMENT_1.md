# 修正案 1（事后补充）：在最强结构里，TTT 是否必要

**性质**：本修正案在看到 Gate A、Gate B 的结果**之后**撰写，属于探索性补充分析。它不修改任何预注册门槛，也不改变 Gate A（`V2_METHOD_NECESSITY=NOT_ESTABLISHED`）和 Gate B（`TTT_ADDED_VALUE=NOT_ESTABLISHED`）的结论。修正案在运行前锁定：文档和代码的哈希写入 `AMENDMENT_1.lock.json`。

## 为什么要补这一项

- Gate B 让三个系统共用同一种读出：log R7 + tanh(网络)，覆盖所有像素。
- 分区结果显示，这种读出在已覆盖像素（TTT α ≥ 0.5，约占有效像素的 72%）上明显弱于冻结的 KF 表：
  - SYS_C 为 0.0504，SYS_B 为 0.0518；
  - B1–B7 的 KF 表为 0.0420。
- 当前最强的系统 B7（V2 配方）正是"KF 表 + 未覆盖修正"的结构，它比 SYS_C 好 0.0079。
- 所以 Gate B 可能低估了 TTT 在最强结构中的作用。要判断 TTT 是否必要，还需要在这个结构里做一次输入匹配的对照。

## 方法

把 B1、B7 结构中所有来自 TTT 的量，换成发布版 DepthSplat 前馈渲染（CACHE 状态，不做 TTT）的对应量，其余全部不变：

- **KF_FF 表**：
  - 与冻结表相同的 KF_BASE 结构：DIS 8 × α 4 × near7 2。
  - 在同样的 FIT_SYSTEM + FIT_SYSTEM2（160 个场所）上，用 KFUSE-V1 的同一段代码（`kf_logic`）拟合：已覆盖像素上的分位数边界，每箱在 21 个权重中选使场所加权 AbsRel 最小者。
  - 只是把 F7 和 α 换成前馈渲染的。
  - **复现检查**：用同一条代码路径、从同一缓存重拟 TTT 表，报告它与冻结表的一致程度（边界最大差、64 个箱中权重相同的个数）。
- **B1_FF**：前馈覆盖像素（前馈 α ≥ 0.5）用 KF_FF 表，其余像素用 R7。
- **B7_FF**：V2 配方用于前馈渲染。
  - 输入：V2Net，前馈渲染的 8 通道基图。
  - 读出：前馈覆盖像素用 KF_FF 表，其余像素用未覆盖修正。
  - 训练设置与 B7 完全相同：留一队列的折、内部验证场所、30 个 epoch、Adam 1e-3、权重衰减 1e-4、每批 8 个查询。
  - 种子 20261631–20261633。
- **评分**：
  - 分区仍按协议的 TTT α 定义，与 B7 的分层是同一批像素；ALL 指标与分区无关。
  - 同时重放 B1（冻结表），核对它与 Phase 1 中 B1 的逐查询误差是否一致。

## 判定（运行前锁定）

- **主比较 P1：B7_FF − B7**，> 0 表示 TTT 在最强结构里有帮助。使用 V1 的配对场所 bootstrap（10,000 次，种子 20260928），合并 350 个场所。
  - 门槛与 Gate B 相同。下列全部满足时，标为 `TTT_ADDED_VALUE_IN_KF_V2_STRUCTURE=SUPPORTED`：
    - CI 下界 > 0；
    - 均值 ≥ 0.002；
    - 中位场所改善 > 0；
    - 最大单个场所正向贡献 ≤ 0.5。
  - 若 CI 上界 < 0（不做 TTT 反而显著更好），标为 `HARMFUL`。
  - 其余情况标为 `NOT_ESTABLISHED`。
- **次要（描述性）**：
  - B1_FF − B1：只用 KF 表时 TTT 的作用；
  - SYS_B − B7_FF：KF 结构对前馈系统的作用；
  - B7_FF − SYS_C；
  - 各折均值、分区像素误差；
  - 运行时间：B7_FF 每个场景约 0.37 s，B7 约 16.6 s，见 RUNTIME_PROFILE.json。
