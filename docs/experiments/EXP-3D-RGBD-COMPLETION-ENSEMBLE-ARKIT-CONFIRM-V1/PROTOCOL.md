# EXP-3D-RGBD-COMPLETION-ENSEMBLE-ARKIT-CONFIRM-V1：归一化 G1 的补全集成在全新真实扫描上的确认

本文件即预注册。锁定时间与哈希见 `preregistration.json`。

## 1. 来源与问题

- 在 EXP-3D-RGBD-ENSEMBLES-ARKIT-V1（80 个 ARKit 验证折扫描）上，补全集成 (调和 + G1) / 2 表面上通过了检验。但事后检查发现：
    - G1 在一半 FAR 像素上塌缩到接近 0 的深度。原因是未归一化的深度读出：深度是 Σ w·t，没有除以可见度。
    - 调和插值在 ARKit 上偏远，两者平均的收益主要是偏差抵消。
- 换成归一化、会弃权的读出之后，平均之后只剩一个小而大致一致的改善。这个读出是：不透明度 ≥ 0.5 处取 深度 / 不透明度，否则用调和插值。
    - ARKit 验证折：+0.046，48/18/14。
    - Hypersim EVAL34：+0.139，64/15。
- 这个读出是在发现问题的同一批数据上事后确定的。本实验在**从没被任何实验用过的新 ARKit 扫描**上做预注册确认。

## 2. 数据

- **EXP-3D-RGBD-ARKIT-CONFIRM-DATA-V1：** ARKitScenes 3dod Training 折。
    - 场馆取种子顺序（20261005）中的第 360–519 位。前 360 位留给试点的 DEV/TRAIN。
    - 每个场馆取视频编号最小的扫描。
    - 帧与规则在读取媒体前锁定，与 ARKIT-VAL-DATA-V1 相同。
    - 按顺序处理，直到 80 个合格；共 67 个不合格。
- **队列：** 80 个扫描、160 个 episode、320 个查询。与 ARKIT_VAL 的场馆不相交（脚本断言）。
- **episode：** 记录 × 角色；上下文 = 角色的 3 帧；查询 = primary_query。
- **G1：** V21 的 G1 载体（V17 L，T24000），3 个种子，由 arms 评估器封存深度与不透明度。

## 3. 读出（FAR = 有效像素中，距上下文重投影 8 像素以外的部分）

- **H3：** REPROJ_HARMONIC。
- **G1N：** 对每个种子，不透明度 ≥ 0.5 处取 深度 / 不透明度，其余取 H3；再对种子平均。
- **HGN：** (H3 + G1N) / 2。
- **对照：** HG = (H3 + G1) / 2，即原来的未归一化读出；H3x0.5 = 0.5 × H3，纯收缩；G1 为原始读出。
- **ALL 版本：** NEAR 中一律用 H3。
- **汇总：** AbsRel；场景值 = 各角色查询平均后再对角色平均。

主检验用 V2 gate；统计用场景 bootstrap，10,000 次，种子 20260928。

## 5. 次要分析（只给标签）

- **FAR：**
    - H3 − G1N；
    - H3 − HG（原始读出）；
    - H3 − H3x0.5（纯收缩）；
    - H3x0.5 − HGN（HGN 是否不只是收缩）；
    - H3 − G1。
- **ALL：** H3 − HGN。

## 6. 完整性与局限

- **完整性：**
    - 读真值之前，arms 封存必须完整，哈希不变。
    - 分析跑两次，结果必须逐字节相同。
    - 本实验只用 CPU。
- **局限：**
    - 只检验补全集成。TTT 集成已在 ARKIT_VAL 上复现。
    - 真值是 iPad LiDAR 的测量。
    - 弃权阈值 0.5 沿用项目一直使用的不透明度阈值，没有调节。
