# EXP-3D-RGBD-DEPTHSPLAT-JEPA-ARKIT-V1：在真实传感器数据上训练逆向 JEPA

**结论：REAL_JEPA_PARTIAL，REAL_DATA_TRAINING_PARTIAL。但修订 1 表明，这个增益几乎全部来自"替换掉一个错误的常数"，而不是补全。**

- **主检验：** 用 ARKit 真实数据训练的逆向 JEPA（JA）在 FAR 上胜过调和插值，+0.210，90/14/55，PARTIAL；也胜过用 Hypersim 训练的 J，+0.231，104/13/42，PARTIAL。两者都只差"≥ 75% 的场景不变差"这一项。
- **增益从哪来：**
    - 约 47% 的评估查询与上下文完全没有重叠。这时调和插值整张图都是 Hypersim 的补洞常数 2.37 m，对室内近景严重偏远。
    - JA 的 FAR 覆盖率达到 0.65（J 0.36，发布权重 0.10），在这些视角上给出合理的室内深度，于是大幅胜过那个常数。
- **对照校准基线就不成立了（修订 1）：**
    - 只把这个常数换成训练折拟合的 1.05 m，FAR AbsRel 就从 0.793 降到 0.418，比 JA 的 0.583 还好。
    - 在校准基线之上加 JA 反而更差：−0.029，57/14/88，HARMFUL。
    - 只看与上下文有重叠的查询，JA 与调和插值打平：+0.027，48/0/50，NOT_ESTABLISHED。
- **结论：** 真实数据训练让模型学会了"室内场景大概多深"，但没有学会基于上下文的补全。
- **探索性：** 归一化 G1 集成（HGN）在有重叠的查询上有一个小的稳定增益（+0.051，67/0/31），两个来源队列方向一致。

## 修订 1：调和插值在 ARKit 上为什么偏远，以及校准基线

**原因：** 修订前在训练折的 728 个查询上查明，只读训练数据：

- **一半查询完全没有上下文命中。** 367 个（50%）查询中，3 个上下文帧的测得深度重投影后一个像素也落不到查询视角里。
- **这时调和插值整张图都是补洞常数 2.37 m。** 这个常数取自 Hypersim 训练集，对 ARKit 的室内近景偏远。这部分查询的 FAR AbsRel 为 1.05，有命中的查询只有 0.38。
- **有命中的查询上，调和插值反而略偏近**（中位 log(H3 / 真值) = −0.32），但按 AbsRel，不缩放已经最优。
- **评估队列同样如此。** ARKIT_VAL 的 320 个查询中 150 个无命中，ARKIT_CONFIRM 中 151 个；两个队列分别有 30 和 31 个场景的所有查询都无命中。相比之下，Hypersim 的 FRESH78 只有 0.6%（2/312），EVAL34 只有 1.2%（4/332）。
- **所以 ARKit 上的"补全"评估有一半其实是"猜一个完全没见过的视角的深度"**，与 Hypersim 不是同一个任务。之前 README 中"偏远可能来自 2.37 m 常数"的猜测成立。

**校准基线 H3CAL（训练折拟合）：** 无命中的查询取常数 1.05 m，有命中的查询保持 H3（k = 1）。训练折上 FAR AbsRel 从 0.742 降到 0.379。

## 解读

- **真实数据训练确实改变了模型。** JA 在 FAR 上的覆盖率从 0.10 升到 0.65，在没见过的视角上给出合理的室内深度。这就是 R1 增益的来源。
- **但这不是补全：**
    - 一个常数（1.05 m）就做得比它好；
    - 在校准基线之上加 JA 反而有害；
    - 在有重叠的查询上它与调和插值打平；
    - 在 NEAR 上它略差。
    - 训练中覆盖率上升、被覆盖像素精度下降，也指向同一件事：模型在学"把空白填上一个合理的室内深度"。
- **训练信号本身可能是问题。** 训练目标从 13 个非上下文帧中均匀抽取，而其中 34% 与上下文完全没有重叠，模型被要求去"补"根本补不出来的视角。EXP-3D-RGBD-DEPTHSPLAT-JEPA-ARKIT-OVERLAP-V1 在本结果出来之前就已锁定，它只在有重叠的目标上训练，在有重叠的新查询帧上评估。
- **归一化 G1 集成的结论需要细化。** 它在有重叠的查询上有小而方向一致的增益，两个队列都是如此，所以 CONFIRM 的结论不是常数造成的假象。但一致性为 68%，达不到 V2 的 75%。在无重叠的查询上它与调和插值一样，都退回到错误的常数。
- **对后续 ARKit 实验的含义：** 无重叠查询应单独处理（例如用校准常数，或不作补全评估）；补全的评估应限定在有重叠的查询上。
