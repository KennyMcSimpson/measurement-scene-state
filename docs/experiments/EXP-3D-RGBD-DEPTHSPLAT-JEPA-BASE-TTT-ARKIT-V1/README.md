# EXP-3D-RGBD-DEPTHSPLAT-JEPA-BASE-TTT-ARKIT-V1：从真实数据训练的逆向 JEPA 基座出发做 TTT

**结论：JEPA_BASE_HARMFUL，JEPA_TRAINING_HARMS_TTT。**

- **Q1：** 以 ARKit 真实数据训练的逆向 JEPA（JA1）为起点做 TTT，比以发布权重为起点更差。ALL AbsRel 为 0.159 对 0.114，差值 −0.0445，好/平/差 15/0/65，HARMFUL。
- **Q2：** 尺度上限同为 3.0 时，JEPA 训练同样让 TTT 变差。0.159 对 0.136，差值 −0.0226，30/0/50，HARMFUL。
- **原因：**
    - TTT 本身在 JA 基座上依然有效：0.266 → 0.159，70/0/10，SUPPORTED。
    - 问题在起点太差。JA 的 7 帧前馈状态覆盖了 97% 的有效像素，但误差很大：发布权重（上限 0.1）为 0.121，JA 为 0.266。
    - 尺度上限本身也有影响。对发布权重做 TTT，上限 0.1 比 3.0 好：+0.022，70/0/10，SUPPORTED。逆向 JEPA 训练用的是 3.0（为了扩大覆盖）。
- **结论：** 这个逆向 JEPA 配方没有为 TTT 提供更好的起点。Core B 目前最好的配置仍是"发布权重（上限 0.1）+ TTT + 与 7 帧重投影取几何平均"。

## 解读

- **"逆向 JEPA 为 TTT 提供更好的起点"这条连接在本配方下被否定了。** 不论对比发布权重的哪种尺度上限，以 JA 为起点的 TTT 都更差。在几乎所有场景上都是如此（Q1 有 65/80 个场景更差）。
- **起点的质量决定了 TTT 的终点。**
    - TTT 只有 100 步，能大幅修正起点：JA 从 0.266 降到 0.159，ZS3 从 0.253 降到 0.136。
    - 但它修不回起点的差距。发布权重在上限 0.1 时的起点（0.121）本来就接近 7 帧重投影，TTT 之后最好（0.114）。
- **尺度上限是关键因素之一。**
    - 上限 3.0 让高斯变大、覆盖率上升，但前馈深度变差，TTT 之后也更差（S6）。
    - JEPA 训练为了扩大覆盖而采用上限 3.0，而且训练把覆盖率推得更高（0.89 → 0.97），这与 TTT 的需要正好相反。
- **对后续的含义：** 如果要用逆向 JEPA 改进 TTT 的起点，训练应在上限 0.1 下进行，并以"7 帧前馈状态的精度"而不是覆盖率为目标。另外，有重叠的目标是否能让训练更有用，见 EXP-3D-RGBD-DEPTHSPLAT-JEPA-ARKIT-OVERLAP-V1。
