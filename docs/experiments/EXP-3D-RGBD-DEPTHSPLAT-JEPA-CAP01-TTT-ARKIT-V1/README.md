# EXP-3D-RGBD-DEPTHSPLAT-JEPA-CAP01-TTT-ARKIT-V1：在 TTT 的尺度上限下训练逆向 JEPA，能否改进 TTT

**结论：JEPA_CAP01_HARMS_TTT，JEPA_CAP01_HARMS_CACHE。**

- **P1：** 把逆向 JEPA 的训练改在 TTT 最好的尺度上限 0.1 下进行（JC1），它作为 TTT 起点仍然略差于发布权重。ALL AbsRel 为 0.121 对 0.114，差值 −0.0070 [−0.0141, −0.0001]，24/0/56，HARMFUL。
- **P2：** TTT 之前的 7 帧前馈状态明显更差。0.173 对 0.121，差值 −0.0517，5/0/75，HARMFUL。
- **改用上限 0.1 消除了大部分损害：**
    - 同为逆向 JEPA 训练，上限 0.1 的 TTT 结果比上限 3.0（JBT 的 JA）好得多：0.121 对 0.159，+0.0375，55/0/25，PARTIAL。
    - 与 7 帧重投影取几何平均后，JC 与发布权重完全打平（都是 0.116）。
- **剩下的差距来自训练目标本身。**
    - 训练损失把未覆盖的像素按全深度惩罚，所以奖励的是"覆盖"而不是"精度"。
    - 这在两个上限下都一样：JC 把前馈覆盖率从 0.73 推到 0.88，精度则从 0.121 降到 0.173。
    - TTT 修回了大部分（0.173 → 0.121，74/0/6），但没有全部修回。
- **结论：** 在当前的逆向 JEPA 目标下，"预训练给 TTT 更好的起点"不成立。要让这条路成立，训练目标需要改成奖励被覆盖像素的精度。

## 解读

- **尺度上限解释了 JBT 中的大部分损害，但不是全部。** 在 0.1 下训练，TTT 结果从 0.159 改善到 0.121，几乎追上发布权重（0.114）；集成之后两者完全相同。
- **训练目标解释了剩下的部分。**
    - 两个上限下，逆向 JEPA 训练都把前馈覆盖率推高、把精度拉低。
    - 原因是训练损失对未覆盖像素按全深度惩罚：只要能把一个像素"覆盖"上，哪怕深度不准，损失也会下降。
    - 对补全（JEPA-ARKIT、OVERLAP）来说，这种偏好部分有用，因为覆盖了原本只能靠调和插值的区域。对 TTT 来说，它损害了起点。
- **TTT 有很强的修正能力，但修不完。** 在 JC 上，TTT 把 0.173 降到 0.121（74/0/6），但没有降到发布权重 TTT 后的 0.114。
- **对 Core B 的含义：** 实用配置不变，仍是"发布权重（上限 0.1）+ TTT + 与 7 帧重投影取几何平均"。如果要让逆向 JEPA 为 TTT 服务，训练目标应改为只奖励被覆盖像素的深度精度（例如归一化深度的相对误差），而不奖励覆盖率。
