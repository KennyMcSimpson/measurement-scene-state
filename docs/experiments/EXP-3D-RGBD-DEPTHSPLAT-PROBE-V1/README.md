# EXP-3D-RGBD-DEPTHSPLAT-PROBE-V1（探索性）

用户 2026-10-05 的指示："DepthSplat用这个作为基座，进行尝试"。本目录记录以 DepthSplat 为基座的探索性检查。
- 基座：cvg/depthsplat @2dad25a7，MIT 许可；base 模型 re10k+dl3dv，448×768，randview2-6。
- 开发队列：主要在 DEV（8 个场景、32 个查询）上进行；扩大规模的开发检查用 EVAL-V3/V4（83 个场景，以前已被多个实验使用）。
- 全部只作描述，没有预注册；没有读取 EVAL_V5、TRAIN_EXT、REPLICA 和受保护的保留集。
- 来源与校验见 [provenance.txt](provenance.txt) 和 [SHA256SUMS](SHA256SUMS)。代码在 [code/](code/)，结果文件在 [results/](results/)，日志在 [logs/](logs/)。
- 预测（npz）和微调权重不在 git 里，路径见 provenance.txt。

## 设置

- **环境**：`~/envs/depthsplat`，torch 2.4.0+cu121。
- **CUDA 光栅化扩展**：diff-gaussian-rasterization-modified @1250c420，glm @5c46b9c0。hit 连 GitHub 不稳定，按用户选择，从本机下载官方 codeload 压缩包再中转到 hit，sha256 见 provenance.txt。用 CUDA 12.2、sm_86 编译。
- **DINOv2 代码**：DepthSplat 用 `torch.hub` 加载 DINOv2 代码。这里改为从本地 hub 缓存加载，`pretrained=False`。
  - 原因：原来的调用每次都要访问 GitHub 判断分支，并下载 ImageNet 权重；而这部分权重已全部包含在 DepthSplat 检查点里，加载编码器时缺任何键都会报错。
  - 缓存代码树的 sha256 与 V31 校验过的 117c2d92… 一致。
- **推理配置**：`+experiment=dl3dv`，`num_scales=2`，`upsample_factor=4`，`lowest_feature_resolution=8`，`monodepth_vit_type=vitb`，`gaussian_scale_max=0.1`，`supervise_intermediate_depth=false`；near 0.5 m，far 200 m。
- **输入**：128×160 帧双线性放大到 256×320。内参归一化为 (cx+0.5)/W；位姿为 OpenCV 约定的 c2w；渲染输出 128×160。
- **渲染深度的含义**：DepthSplat 渲染的深度是 Σα·T·z（零背景），**没有按累积不透明度归一化**。因此同时渲染了累积 α。打分中：
  - "覆盖"指 α ≥ 0.5；
  - DSN = z/α，只在覆盖处有值；
  - FAR_DSN_SCALED = NEAR 区域和未覆盖的 FAR 区域用调和填充，已覆盖的 FAR 区域用 DSN。
- **深度单位**：深度一律换算为沿射线距离，与记录一致：Hypersim `depth_meters`，项目里的射线是单位方向。
- **区域与基线**：
  - FAR = V17 的 NEAR 掩码之外的有效像素，NEAR 掩码由 3 个 RGB-D 上下文视角重投影、取 8 px 邻域得到；
  - 调和填充 = REPROJ_HARMONIC；
  - G1 = V21 的 G1，T24000；DEV 上用 3 个种子，EVAL34 上用 1 个种子；
  - 基线都由通用 arms 评估器封存，查询深度只在打分时读取。
- **GPU**：4 号卡，与另一用户常驻的 1.3 GB 进程共用（用户 10/5 批准）。启动命令为 `cv_gpu_run.sh --with-others`，日志里标记为 co-tenant。
- **代码版本**：DEV 的运行早于位姿正交化和 `--min-query-gap` 选项。这两项改动不影响 DEV 已有运行的设置；DEV 位姿已正交到 1e-6。归档的 [code/ds_predict.py](code/ds_predict.py) 是最终版本。

## 1. 零样本（只用 RGB，3 个上下文视角）

| 方法（DEV，AbsRel） | ALL | NEAR | FAR |
|---|---:|---:|---:|
| REPROJ_HARMONIC | 0.2059 | 0.1438 | 0.3284 |
| G1（3 个种子） | 0.3217 | 0.3291 | 0.3274 |
| DepthSplat 渲染深度 | 0.5184 | 0.4420 | 0.8771 |
| FAR_DSN_SCALED | 0.2138 | 0.1438 | 0.3618 |

- DepthSplat 在上下文视角上的深度：AbsRel 0.142，δ1 0.83。实测与预测的比值中位数为 0.99，所以尺度基本是公制。
- FAR 区域的覆盖率只有 13%。

## 2. 相机约定自检（渲染回上下文相机本身）

| 变体 | 上下文自渲染 PSNR（均值，范围） | 渲染深度与编码器深度的 AbsRel | 查询 PSNR |
|---|---|---:|---:|
| 采用的约定（c2w，+0.5） | 20.8 dB（11.8–28.7） | 0.086 | 14.5 dB |
| 改传 w2c | 15.8 dB（7.6–23.8） | 0.325 | 10.7 dB |
| 去掉 +0.5 | 19.6 dB（11.7–26.3） | 0.084 | 14.3 dB |

采用的约定在各项上都最好，所以结果差不是接线错误。即使渲染回自身视角，PSNR 也只有 20.8 dB，说明多视角深度之间不一致。

## 3. 用实测深度替换 DepthSplat 的上下文深度

做法：把最终上下文深度换成实测深度（平面 z，最近邻放大），保留 DepthSplat 的特征、匹配概率和高斯参数头。

结果：
- FAR 覆盖率从 13% 降到 4%。之前的覆盖来自位置放错的高斯。
- FAR_DSN_SCALED 的 ALL / NEAR / FAR 为 0.2058 / 0.1438 / 0.3295，与调和填充几乎相同。
- 原因：高斯只能放在观测到的表面上，碰不到 FAR。

## 5. 用 TRAIN 数据微调 DepthSplat 的深度预测器

做法（[code/ds_finetune.py](code/ds_finetune.py)）：
- 数据：TRAIN72 加上 SEG-V1 的 240 段，共 312 条记录。
- 采样：每步随机取 3–6 帧 RGB。
- 损失：每个视角的 log-L1 深度损失，在 128×160 上计算。
- 训练范围：只训练深度预测器，ViT 用十分之一学习率；高斯参数头保持发布版本；模型保持 eval 模式。
- 步数与选择：固定 4000 步，取最后一步，不做选择。DEV 曲线只作记录。

| ft_v2 | 5e-6（5e-7） | 0.1416 / 0.1062 / 0.0967 / 0.1012 / 0.1073 / 0.1089 |

| 变体（DEV，调和 − FAR_DSN_SCALED，FAR） | 零样本 | ft_v1 | ft_v2 |
|---|---|---|---|
| 无额外帧，RGB | −0.0334 | −0.0310 | −0.0504 |

ft_v2 让单视角深度明显变好：AbsRel 从 0.142 降到 0.109，δ1 从 0.83 升到 0.85。但 FAR 没有一致的改善。

## 读法

1. **原任务上没有价值。** 在原任务（3 个 RGB-D 上下文）上，DepthSplat 不起作用：
   - 零样本只用 RGB 时，远差于调和插值；
   - 注入实测深度后，与调和插值相同；
   - 像素对齐的高斯只能落在观测到的表面上，碰不到 FAR。
2. **额外的只有 RGB 的帧：收益主要来自紧邻查询的帧。**
   - 在 EVAL34 上，FAR 改善很大：相对调和填充 +0.135，与 G1 相当；和 G1 组合后再好 +0.041。
   - 但一半的查询里，相邻帧就在额外帧中。去掉帧序距查询 < 3 的帧后，相对 FAR_G1 不再有收益（−0.005）。
   - 也就是说，DepthSplat 在这里起的作用大致是"估计一张相邻 RGB 图的深度"。
3. **微调改善了单视角深度，但不改变结论。** DEV 上下文深度 AbsRel 从 0.142 降到 0.109，在 EVAL34 上的结果与零样本相同。
4. **测量覆盖仍是 FAR 的主导因素。** 同样这些帧如果有实测深度，即使去掉相邻帧，相对 FAR_G1 仍好 +0.078 [+0.009, +0.131]（62/10）。这与 V24/V25/V27 和 Core B 的结论一致。
5. **DEV 太小，不足以评价这类方法。** DEV（8 个场景）和 EVAL34 的结论方向不同：DEV 的 FAR 对调和插值容易得多（0.328 对 0.487）。
6. **没有做预注册确认。** EVAL_V5、TRAIN_EXT、REPLICA 都没有动用。原因是排除相邻帧之后，没有可以确认的效应。
