# EXP-3D-RGBD-DEPTHSPLAT-TTT-ABLATION-V1：TTT 的收益来自学到的基座吗？

**结论：LEARNED_BASE_MATTERS。**

- 用同样的测试时优化，从学到的 DepthSplat 状态出发，比从"无网络高斯"出发好：P1 = +0.024 [+0.008, +0.044]，61/78 个场景更好，SUPPORTED。无网络高斯是把每个测得像素直接变成一个高斯。
- 不做 TTT 时，两者没有区别：P2 = +0.006，47/31，不成立。
- 所以学到的基座的价值，不在前馈预测本身，而在为测试时优化提供了更好的起点和参数化。同样 100 步，学到的状态收益是 +0.030，无网络高斯只有 +0.012。

**说明：**

- 预注册见 [PROTOCOL.md](PROTOCOL.md)。2026-10-08 06:25:19 锁定，sha256 `cebe6e23…`。
- 无网络高斯的设置只在 DEV 上选择，见 `development/` 与 `nv_selection.json`：
    - 尺度 c = 0.0625，即光栅化器低通下的点状高斯极限；
    - 不透明度 0.95；
    - TTT 步长 m = 1。
- 评估队列 FRESH78（78 个场景），episode、流帧、查询都与 V1 相同。ZS 的各臂直接引用 V1 已封存的预测。
- 统计单位是场景，bootstrap 10,000 次，种子 20260928，判定用 V2 gate。分析运行两次，结果逐字节相同。

## 解读

- **前馈状态没有优势：** 在注入测得深度之后，DepthSplat 的前馈高斯与直接由测量像素生成的点状高斯几乎一样好（P2）。网络在已测区域没有加入额外的几何信息。
- **TTT 下有优势：** 在同样的测试时优化下，学到的状态稳定地更好（P1，61/78）。可能的原因是：DepthSplat 给出的高斯带有学到的各向异性尺度、朝向与不透明度，测试时优化在这个参数化上收敛得更快、更好；点状高斯的尺度梯度被光栅化器的低通"吃掉"，主要只能调整位置、颜色和不透明度。这一点没有直接检验，只是推测。
- **对 Core B 叙事的含义：** "在学到的场景状态上做测试时写入"的价值是真实的，而且确实依赖学到的状态，不只是经典的逐场景高斯拟合。但收益仍局限在已测区域，不会补全没看到的几何。

## 完整性与开发记录

- NV 的预测在读真值前全部封存，`query_depth_read = false`，读取前逐个校验哈希。ZS 的封存直接引用 V1。
- DEV 选参过程：
    - 原定尺度网格 {0.5, 1, 2} 选在边界上，于是向下扩展到 {0.0625, 0.125, 0.25}。c ≤ 0.125 后曲线走平，因为光栅化器的低通决定了足迹。
    - m 网格 {1, 3, 10} 在 c = 0.5 与 c = 0.0625 上都选出 m = 1。
    - 全部记录在 `development/`。
