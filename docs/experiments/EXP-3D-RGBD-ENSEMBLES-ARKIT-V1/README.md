# EXP-3D-RGBD-ENSEMBLES-ARKIT-V1：两个集成在真实传感器数据（ARKitScenes）上的检验

**结论：**

- **TTT 集成在真实数据上复现：B1 = TTT_ENSEMBLE_CONSISTENT，B2 = TTT_NEEDED。**
    - √(REPROJ7 × TTT) 在 71/80 个真实扫描上胜过 7 帧无模型重投影（+0.0049，SUPPORTED）。
    - TTT 是必要的：60/80（SUPPORTED）。
    - TTT 单独也稳定胜过无模型重投影（62/18）。
    - 但绝对收益小：ALL AbsRel 从 0.121 降到 0.116（集成）或 0.114（TTT 单独），相对约 4–6%。
- **补全集成没有在真实数据上得到可信的复现：A1 = ENSEMBLE_PARTIAL，A2 = JEPA_NO_ADD。**
    - 预注册主检验 (调和 + J + G1) / 3：+0.422，56/24，PARTIAL。
    - (调和 + G1) / 2 为 60/20，恰好达到 75% 的门槛（SUPPORTED）。
    - 但事后检查表明，这主要是偏差抵消，而不是学到的补全提供了信息（见下文）。
    - 逆向 JEPA 在 ARKit 上单独不比调和插值好（−0.023），加入集成也没有帮助（−0.009）。

## 探索性事后检查：补全集成的收益从哪里来（未预注册，`exploratory_posthoc/`）

在 ARKit 上，G1 的 FAR AbsRel 的 90 分位和最大值正好都是 1.0：它在大量像素上输出接近 0 的深度。这是旧载体的读出方式造成的：深度是 Σ w·t，没有除以可见度（V22 发现的偏差），不透明度低时深度就塌向 0。为此做了逐场景检查，同样的检查也在 Hypersim 的 EVAL34 上做了：

| FAR | ARKit | EVAL34（Hypersim） |
| --- | ---: | ---: |
| G1 塌缩（G1 < 0.25 × H3）的像素比例 | 0.53 | 0.07 |
| H3 中位对数偏差 log(预测 / 真值) | +0.10（偏远） | −0.06 |
| G1 中位对数偏差 | −3.65 | −0.21 |
| 纯收缩 0.5 × H3 相对 H3 | +0.305，35/45 | −0.086，19/60 |
| 纯收缩 0.75 × H3 相对 H3 | +0.205，45/35 | +0.021，27/52 |
| HG 相对 0.5 × H3 | +0.126，45/18/17 | +0.218，67/12 |

**读法：**

- **在 Hypersim 上：** 调和插值基本无偏，单纯收缩只会变差，HG 远好于 0.5 × H3。补全集成的收益来自 G1 提供的信息，COMPLETION-ENSEMBLE-V1 的结论成立。
- **在 ARKit 上：** G1 迁移失败，一半 FAR 像素塌缩到接近 0。在 18 个场景里，HG 与 0.5 × H3 完全相同。调和插值在 ARKit 上偏远；把它减半本身就能改善均值，但不稳定（35/45）。所以 ARKit 上 HG 的"通过"，很大一部分是两种相反偏差的抵消，不能当作学到的补全在真实数据上有效的证据。

### 归一化的 G1 读出（事后，`exploratory_posthoc/norm_g1_check_*.txt`）

- **读出定义：** G1N 在不透明度 ≥ 0.5 处为 深度 / 不透明度，其余为 H3，再对种子平均；HGN = (H3 + G1N) / 2。
- **ARKit：**
    - G1 在 50% 的 FAR 像素上不透明度 < 0.5，即正好是塌缩区域。
    - HGN 相对 H3：+0.046 [+0.025, +0.068]，48/18/14（中位数 +0.005）。G1N 单独：+0.039，41/18/21。
    - 去掉偏差抵消之后，学到的补全在真实数据上只剩一个小而大致一致的改善。
- **EVAL34：** G1 只在 0.9% 的像素上弃权，HGN 为 +0.139，64/15，与 HG 一致。
- **复现：** 这个读出要在新的真实扫描上预注册复现，见 EXP-3D-RGBD-COMPLETION-ENSEMBLE-ARKIT-CONFIRM-V1。

## 解读

- **TTT 在真实传感器上站得住：** 在学到的 DepthSplat 状态上做测试时优化，再与测量驱动的重投影平均，稳定优于无模型方法；TTT 本身也是必要的。真实 LiDAR 测量已经相当准（R7 的 ALL 中位数 0.084），所以绝对收益小。
- **学到的补全在真实数据上没有得到支持：**
    - 旧载体 G1 只在合成数据上训练，在 ARKit 上大面积失效。
    - 新基座上的逆向 JEPA（J）在 ARKit 上只覆盖 38% 的 FAR，单独不比调和插值好。
    - 合成数据上通过的补全集成，在真实数据上的表面通过来自偏差抵消。
- **对整个项目的含义：** Core B（测试时写入）有跨数据来源的稳定证据。Core A（学到的补全）的价值目前只在合成数据上成立，在真实数据上需要能迁移的补全模型；至少需要在真实数据上训练，或使用归一化的深度读出。
