# EXP-3D-RGBD-WIDTH-DATA-V15 计划：更多数据时宽度是否起作用

- **写定：** Claude，2026-09-30（远端时间），在 V14 完成及其事后分析之后、任何 V15 训练之前。
- **资源：** 全程 CPU（8–23 号核，单线程 BLAS），GPU 暂停。
- **修改规则：** 本计划写定后，配方、评价与判定都不得根据任何 V15 结果修改。

## 0. 问题

- **V12：** 在 72 个训练场景上，把宽度从 32 加到 64，补全只改善 +0.004（CI 跨零）。
- **V14：** 宽度 32 不变，训练场景从 72 增加到 127，被看到区域的精度改善，补全却变差。事后分析显示，这在每一个相同训练步数上都成立（探索性）。
- **假设：** 容量与数据之间存在取舍。更多样的数据需要更大的模型，补全才会改善。
- **本轮问题：** 在 127 个训练场景上，把宽度从 32 加到 64，补全能否改善？改善后的组合能否胜过经典补洞？

## 1. 设计

- **配方：** 与 V11 C1 / V14 C1 完全相同（32³ 网格，CONTEXT_DEPTH bounds，冻结的 V2 C1 损失，6000 步，Adam 1e-3，可变 3–7 视角，冻结的 DEV 选择规则，3 个 seed）。
- **训练集：** 两个变体都用 TRAIN72 + TRAIN-EXT，共 127 个场景（与 V14 C1 相同）。
- **变体：**
  - C0：宽度 32（hidden 32、expansion 64，64,238 个参数）。它就是 V14 C1 的配方，训练记录、DEV 曲线、选中的 checkpoint 与评价预测都必须与 V14 C1 逐位相同，否则停止。
  - C1：宽度 64（hidden 64、expansion 128，250,542 个参数）。每个 seed 的初始参数与 V12 C1 相同。
- **代码：** 由 V14 的文件逐字派生，只改变体表、参数量、对照与报告文字；V14 的两处修正（本变体自己的训练集、DEV 曲线不存状态）保留。
- **执行：** 6 个训练并行，每个占一个核。

## 2. 评价

- **主队列：** 与 V14 相同，即 EVAL-V3 ∪ EVAL-V4 的近处 query，共 83 个场景；EVAL-FAR 只作描述。
- **封存：** 所有预测在读取 query 深度之前封存。封存之前，C0 的每个预测都必须与 V14 已封存的 C1 预测一致（最大差 ≤ 1e-6）。
- **主判定：**
  - **P1：** WIDTH_AT_SCALE_GAIN = FAR AbsRel(C0) − FAR AbsRel(C1)，冻结的 V2 gate（与 V11 COMPLETION_GAIN 同一定义与同一函数）。
  - **P2：** AbsRel(REPROJ_HARMONIC) − AbsRel(HFILL8 of C1)，INPAINT-V1 的标签规则。
- **分支：**
  - A：P1 SUPPORTED 且 P2 ABOVE。更多数据下宽度改善了补全，并在组合中胜过经典补洞。
  - B：只满足其一。
  - C：两者都不满足。
- **描述性：**
  - **2×2：** 在同一批场景上，与已有的两格比较：宽度 32 / 72 个场景（V14 C0 = V11 C1，取 V14 的封存预测），以及宽度 64 / 72 个场景（V12 C1 已选中的 checkpoint，在本轮评价阶段渲染）。交互作用为 [FAR(32, 72) − FAR(64, 72)] − [FAR(32, 127) − FAR(64, 127)]。
  - **最后一步：** C0 与 C1 第 6000 步 checkpoint 的结果。V14 的事后分析显示补全在最后一步最好，所以这只作描述。
  - **其他：** AHFILL8（阈值 0.5，描述性）、DEV 结果、训练曲线、各队列分别的结果。

## 3. 禁止项

- 不得根据任何结果修改配方、步数、选择规则、评价队列、判定或分支。
- 不打开 FRESH 与受保护的 final holdout。
