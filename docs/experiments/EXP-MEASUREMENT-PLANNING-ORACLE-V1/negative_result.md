# 负面结果：预算化深度采集在现有数据上没有可学习的决策余量

**结论：** 在已有 Hypersim 记录上，"该测哪几帧"的可推广余量约为 0.005 AbsRel，且不显著。一条简单规则"测最新的帧"已经拿到 oracle 可推广收益的几乎全部。按预注册的停止规则，BUDGETED-MEASUREMENT-PLANNING 方向停止方法开发：不训练效用预测器，不训练策略。

## 证据

- **主判定不成立：** EVAL34（83 个场景），K ∈ {1, 2, 4}。最强可部署规则对交叉查询 oracle 的差距：
    - K = 1：+0.0054 [−0.0043, +0.0157]，35/16/32；
    - K = 2：+0.0044 [−0.0037, +0.0129]；
    - K = 4：−0.0006 [−0.0083, +0.0065]。

    三者都没有通过 V2 gate。
- **样本内 oracle 的余量不可推广：** 样本内余量为 +0.025、+0.021、+0.013，区间都不含 0，但这部分只在被打分的那个查询上成立。换成另一个查询来挑帧，它几乎消失；在远处查询上甚至比覆盖规则更差，K = 2、4 时判为 HARMFUL。
- **知道查询相机也帮不了多少：** QUERY_NEAREST 用查询相机选最近的候选帧，K = 1 时 0.1922，LATEST 为 0.1974。
- **两个次要分析结论一致：** 排除相邻帧（GAP3）与远处查询（EVAL_FAR）都没有可推广的余量。

## 为什么会这样

- **主导因素是"查询附近有没有测量"：** 在这些记录里，查询多在轨迹末端，所以最新的帧就是离查询最近的帧，LATEST 自然最强。
- **规则与任务结构的关系：** 查询不在末端时（远处查询），覆盖类贪心最强，但 oracle 的额外优势同样只针对具体查询，不能推广。
- **收益很快饱和：** 第一帧深度的平均边际效用约为 0.051，第四帧只有 0.012。9 帧全测甚至比最好的 5–6 帧略差，所以"多测"本身也不是越多越好。

## 这个负面结果不说明什么

- 不说明测量没有价值：只测 1 帧深度，误差就从 0.289 降到约 0.17–0.20。
- 不说明在别的设定里不存在余量：
    - 在线、看不到后续帧的设定，本阶段没有测；
    - 更长的轨迹、查询分布未知的场景、真实传感器噪声，也都没有测。
- 不说明有不确定性的状态表示（例如 3DGS 加 FisherRF 式 EIG）一定没用。本阶段只用了无模型后端。但交叉查询 oracle 用的是部署时拿不到的邻近查询真实效用，它也只与 LATEST 打平，这说明在这批数据上可推广的收益空间很小。

## 如果将来要重启

- **新任务设定：** 在一个新的、预先写定的任务设定上重做 oracle 余量审计。例如更长的轨迹、未来查询分布与轨迹末端无关，或者真实传感器（ARKitScenes）。
- **数据：** EVAL-V5 与 TRAIN-EXT 没有被本实验读取，可以作为那时的开发或确认数据。
- **必须保留的基线：** LATEST、覆盖类贪心与交叉查询 oracle。任何方法都必须先在等预算下胜过它们。
